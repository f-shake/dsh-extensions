# 修复：窄屏下设置浮层被压成半截（含视口 100vh = 0 的垫片问题）

> 状态：**已完成**（阶段二开发 + 阶段三复核均通过）。
> 版本：dsh-remote-android 1.0.39（versionCode 40），WebView 157。
> 落地文件：`web/WebCompat.kt`、`ui/web/WebScreen.kt`、测试 `WebCompatViewportTest.kt`。

## 1. 现象与目标

- 现象：平板竖屏（720×1068 CSS）打开 DSH 设置，白色面板只占屏幕上半截（约 400px 高），下方露出后面的文件树/对话；横屏（1152×636 CSS）正常。
- 目标：竖屏恢复成页面设计的全高抽屉；横屏与桌面行为不变。
- 非目标：不改 DSH 前端（页面 CSS 在健康浏览器里是对的）。

## 2. 真机实测

设备：小米平板 23046RP50C，Android 15，WebView `157.0.8103.38`，物理 1800×2880 @400dpi → CSS **720×1068**。

修复前，应用内 `诊断信息` 的实时探针（`logcat -s DSHPROBE`）：

```
vh=0  innerH=1068  viewW=720  viewH=1068  rootH=1068
.VOzbGW_overlay   t=0   h=0     pos=absolute   offsetParent=BODY(position:static)
.VOzbGW_panel     t=-400 h=800  ← 往上偏了 400
```

## 3. 根因（两条叠加）

1. **容器没有高度**：设置浮层是 `<body>` 的直接子节点，移动端规则是 `position:absolute; height:100%`。没有定位祖先时，这个百分比对着「初始包含块」解析，而它的高度正是 0 → 浮层高 0。
2. **垫片改错了方式**：旧实现把带 vh 的规则抄进一张 `!important` 覆盖表，等于用桌面规则覆盖所有宽度，把面板钉成 `min(800px, 1068-48)=800px`。800 高的面板在 0 高的 flex 居中容器里被垂直居中，顶端 −400 → 屏幕上只剩下半截。

## 4. 方案

### 4.1 视口单位改成「就地改写声明」

直接对原样式表里的声明 `setProperty`，优先级沿用 `getPropertyPriority`，不再另插覆盖表。层叠顺序、媒体查询、`@layer`、选择器权重全部保持页面原样，窄屏 `height:100%` 自然胜出。

- 原值记在 `WeakMap<CSSStyleDeclaration, {属性: {原值, 优先级}}>`：改写后值里不再含 vh，重算必须拿原值算。
- **只在 `100vh` 不可用时才改写**（判据见 4.3）；健康设备一个字节都不改。

### 4.2 给浮层一个确定高度的包含块

判定 `100vh` 不可用时，除钉 `html/body/#root` 的高度，再写一条 `body{position:relative}`：`body` 已被钉成视图高度，变成定位祖先以后浮层的 `height:100%` 就解析成 1068，遮罩同时回到全屏。

- 选 `body` 而不是 `#root`：实测 `overlayParents = [overlay, BODY, HTML]`，浮层就挂在 body 下。
- `position:relative` 不会给 `position:fixed` 后代创建包含块，桌面端居中弹窗不受影响。

### 4.3 判定「100vh 不可用」

探针元素实测 `height:100vh`，与 `window.innerHeight` 比对：**差值超过 1px 就算不可用**（含 0，也含旋转后缓存下来的旧值）。每次判定都重新测量；量不到（body 未显出）时沿用上次结论，不把「没量准」当成「健康」。

### 4.4 补丁失效的兜底

就地改写的代价是补丁写在页面自己的声明里，页面一旦重建样式表就失效。两条兜底：

- 观察器新增 `characterData` 与「文本节点插进 `<style>`」两种信号，命中即重新扫描；
- 每次重扫都用当前可见的声明集合剪掉失效对象（`vhSeen.delete`），避免每次 resize 的循环越扫越长。

## 5. 影响面与风险

| 项 | 说明 |
|---|---|
| 改动文件 | `web/WebCompat.kt`、`ui/web/WebScreen.kt`、新增测试、本计划文档 |
| 风险 1 | 页面重建样式表导致补丁失效 → 4.4 的两条兜底覆盖 |
| 风险 2 | `body{position:relative}` 可能改变个别绝对定位后代的参照物 → 健康浏览器里 body 与初始包含块同尺寸同位置；坏设备里原本就是 0 高，属于修好 |
| 风险 3 | 健康设备路径没有真机可验 → 只有静态守卫，逻辑上「不改写、不钉高」 |
| 回滚 | 改动集中在两处，可单独回退 |

## 6. 测试与验证

**JVM 契约测试**（`WebCompatViewportTest`，8 条）：断言的是脚本结构——就地改写的完整调用（含优先级）、`applyViewportUnits` 的落点与顺序、`100vh` 判据、`body{position:relative}`、原值留存、重建兜底与剪枝、不动 url/字符串、返回键脚本不受影响。

**真机验证**（平板，ADB）：

| 场景 | 结果 |
|---|---|
| 竖屏设置 | 面板 `h=1068`、遮罩 `h=1068`，全屏抽屉 |
| 横屏设置 | 面板 `h=588` = `min(800, 636−48)`，居中弹窗 |
| 键盘开合后再开设置 | 面板仍 `1068`，补丁没有失效 |
| 探针复核 | `overlayOffsetChain = [overlay, BODY(position:relative, h=1068)]` |

**未覆盖**：健康设备（`100vh` 正常）路径没有真机，仅静态守卫；全量单测未跑。

## 7. 验收标准

- 竖屏设置面板 `getBoundingClientRect().height === 1068`，遮罩全屏。
- 横屏弹窗高度 = `min(800, innerHeight-48)`。
- `100vh` 正常时不写任何根节点样式。

## 8. 实施记录

- 2026-11-08：定位（真机复现 + `DSHPROBE` 探针）→ 实现 → 契约测试 → 平板四场景验证 → 独立复核 10 条意见逐条处置（8 条属实、2 条部分属实，全部修复）。
- 复核中被指出并修正的点：文档与实现相反的 3 处、`viewportBroken` 一次性缓存的两种误判、`vhRules` 强引用导致的只增不减、`<style>` 内容被原地重写后补丁丢失、诊断探针里的构建哈希类名与写死坐标、测试只断言文本不足以钉住行为、`setWebContentsDebuggingEnabled` 的重复调用（`DshWebView.kt` 里 HEAD 已有，本次改动已撤回）。
- 第二轮复核又指出 3 条修复带来的新风险，已按序处置（不是「全部修复」收尾，而是带着这三条一起改）：
  - 判定被挪进 resize 热路径：改为按 `innerHeight` 缓存结论，视口高度没变不再插探针强制布局。
  - 一次性补丁不撤销：引入 `vhPatched`，一旦写过补丁就继续按当前高度维护，不再因某次误判翻回「健康」而撒手。
  - 剪枝误删 disabled 表的原值：扫描时不再跳过 `sheet.disabled`，切主题换表后仍接得上。
  - 另补 `<link>` 原地换 `href` / 切 `media` 的重扫信号（观察器加 `attributeFilter`）。
- 副作用（已知、接受）：判定按高度缓存后，同一高度内的瞬时误判不会重复纠正；`vhPatched` 一旦置位就不再撤销，属于「宁可继续修也不中途撒手」的取舍。
- 最终验证：契约测试 10 条通过；平板竖屏 `panel.h=1068`、横屏 `panel.h=588`（= `min(800, 636-48)`）。
