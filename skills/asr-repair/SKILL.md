# ASR 转写稿修复（asr-repair）

一句话契约：**只改「听错 / 写错」的地方，不改「怎么说」；正文干净、改动有据、拿不准的标出来问人。**

## 0. 开工前：先读个人词表（有则必读）

个人词表在**本技能目录**下的 `personal/glossary.md`（本机安装位置 `%USERPROFILE%\.dsh\skills\asr-repair\`；本机是目录联接，与仓库 `skills/asr-repair/` 是同一份文件）。它是本机专名的**唯一真源**（人名、单位、产品、地名、口头禅都在那儿，不在本文件里）。

- **存在就先整篇读完，再动正文。** 不读词表直接改，等于把已经确认过的专名重新猜一遍，必错。
- 不存在（换机器、新装、分享来的版本）就只用本文件的通用规则，并在回复里说明「未带个人词表」。
- 想从零建一份：把 `references/glossary-template.md` 复制成 `personal/glossary.md`，照表填。
- 词表与本文件冲突时：**词表优先**，但仍要看上下文；词表里标「待核实」的条目**不要**自动套用。
- 长稿先用 §9 的脚本扫候选。

## 1. 适用范围

**用**：口述日记 / 生活记录、录音转写的会议与工作日志、语音输入写的随笔草稿（公众号初稿等）。

**不用**：
- 要求润色成书面语、重写、压缩篇幅的稿子（那是改写，不是修复）；
- 手写稿的普通错别字 / 病句校对；
- 把音频、视频转成文字本身——本技能只处理**已经成文**的稿子。

## 2. 四条原则

1. **准确**：专名、同音字、单位、数字这类硬错误必须改。
2. **通顺**：只在粘连、语序明显别扭处做最小调整。
3. **保留风格**：语气词、口头禅、方言口语原样留，不改成书面腔。
4. **克制**：不改原意、不新增信息、不删内容。**判据**：没有专名的句子，改完应读作「原文更顺」，而不是「另一个人写的」。

> 反向指标：如果一段里没有专名却成片被改，或者全文改动率很高，先停下来怀疑自己是不是在改写。

## 3. 处理顺序

1. **通读全文**——先弄清时间线、人物、场景，再动第一处。
2. **修专名**：人名职务 → 单位机构 → 术语产品 → 地名店名，一边改一边建「正确词 → 全文统一」映射。
3. **修同音 / 近音**：靠上下文和语义判断，不靠字面。
4. **修多字漏字、数字与单位**。
5. **标点与分段**。
6. **核对代词与性别**，再全局一致性检查（同一专名有没有混用）。
7. **自检**（§10）。

## 4. 四类专名误听：怎么认，而不是背表

具体词条在个人词表里；这里只给**判断信号**，换个人、换领域照样用。

**1）人名 / 职务（最高优先）**
- 信号：姓 + 职务（X 主任 / X 所 / X 局）、称呼突然出现却没交代、同一人前后两种写法、女性人物被写成「他」。
- 常见错法：同音姓氏（张 / 章、王 / 汪、陈 / 程）；职务简称被听成日常词（把「王所」听成「网所」）。
- 处置：确认后**全文统一**；已知女性统一用「她」；只出现一次又核对不了的，保留并列入待确认。

**2）单位 / 机构**
- 信号：「院 / 员」「室 / 事 / 市」「所 / 锁」这类同音；机构简称后面直接跟动作。
- 处置：以官方全称或公文简称为准；拿不准就保留原字。

**3）术语 / 产品**
- 信号：英文混写、大小写忽高忽低、版本号型号、行业黑话、品牌名。
- 常见错法：英文按读音转成汉字；缩写丢大小写（`wifi` → `WiFi`）。
- 处置：统一为官方写法；同一个产品全文只留一种写法（两种并存时看后文哪个多、哪个像官方）。

**4）地名 / 店名（最高风险）**
- 信号：地铁站、路名、商场、连锁店、公园；同音字（浦 / 铺、城 / 成、桥 / 侨）。
- 处置：优先官方名——地铁站名以运营方为准，连锁店写清分店名。**这一类的「合理推测」最容易闯祸，见 §6。**

> 更细的误听机理（口音、连读、OOV、数字、英文、改口重复、断句）见 `references/asr-error-patterns.md`；稿子错得离谱时先读它。

## 5. 非专名的通用修正

| 类别 | 典型 | 处理 |
|---|---|---|
| 语气冗余 | 多余的「了」；「嗯」 | 「嗯」属识别噪声，**无条件全删**（不区分位置和语气）；多余的「了」删 |
| 多字 / 重复 | 发发到、买了了、西西北角 | 删重复；「买了了」这类要补量词（买了一个） |
| 漏字 | 「20 分」 | 按上下文补（20 分钟），补不出单位就保留并标存疑 |
| 单位写法 | `160 KM每H`、中文数字加「每小时」 | 统一 `160km/h`、`110km/h` |
| 用词规范 | 「好好的」「好好的做」 | 副词用「地」：`好好地` |
| 数字 / 时间 | 「五七」与「57」混用 | 统一阿拉伯数字；时间线矛盾按上下文推断，**标存疑** |
| 标点 / 分段 | 一逗到底 | 该句号就句号；按场景分段优于按时间流水 |
| 格式 | 中文与英文、数字之间留空格 | 默认**不留空格**（如 `500G`、`7号线`、`M90`） |
| 轻微语序 | 「不是睡得特别好」 | 只调明显别扭处（→「睡得不是特别好」），不改表达习惯 |

方言和口语词（「咋回事」「整」「弄」）**不算错**，不要按普通话标准改写。

## 6. 拿不准的时候：安全阀（优先级高于一切美化）

1. **能查就查**：联网搜索、地图、官网、公众号。**至少两个独立来源一致**才改；只有一个来源的，标存疑。
2. **查不到就原样保留**，列进「待你确认」。**不要**用方位、车程、上下文「看着合理」去替换——真实教训：有人把本地一座真实存在的山按方位推断改成了另一座山，联网核实后才改回来。
3. **用户给了正确写法**：按用户的改，并把这条补进词表（§7）。
4. **硬信息只保留不改**：型号、公式、账号、金额、身份证/车牌、菜名价格。除非用户确认。
5. **修正说明只列真正改动**；没动的专名要明说「按原口述保留」，别让人以为你偷偷改了。

## 7. 维护个人词表（用户确认后才写）

触发：用户纠正了某个词、说「以后 XX 都写成 YY」、或同一个词错了两次以上。

- 只记「误听写法 → 正确写法 → 一句依据」；不记整句，不贴隐私上下文。
- 写进**本技能目录**的 `personal/glossary.md`（本机即 `%USERPROFILE%\.dsh\skills\asr-repair\personal\glossary.md`，与仓库那份是同一文件）里对应小节；没有合适的节就先加表头。
- 一次只收**确认为真**的条目；词表里原本标「待核实」的，不因为「看着像」就转正。
- 不把一次性信息（某次活动名、只出现一次的路人）塞进词表——词表只放长期复用的。
- 写完回一句「已记入词表：X → Y」，不要静默写文件。

## 8. 输出格式

```
<修正后的完整正文>

---

**修正说明**
- 专名：王主任（原「汪主任」，3 处）……
- 同音：报到（原「报道」，活动签到）
- 格式：单位统一 `km/h`、中英文之间**去掉**空格
- 未改动：文中的站名、店名按原口述保留
- 待确认：「XX」指 A 还是 B？
```

- 正文里**不要**夹批注、不要 `[sic]`、不要改一处写一个括号解释。
- 改动多时按类别汇总，同类只举 1–2 例 + 处数，别写逐条流水账；改动少就直说「仅 N 处」，别硬凑。
- 输出到文件时：**默认另存副本**（`<原名>.fixed.md`），不覆盖原稿；用户明确说覆盖才覆盖。

## 9. 扫描脚本（可选，长稿建议先跑）

```powershell
pwsh -NoProfile -File "$env:USERPROFILE\.dsh\skills\asr-repair\scripts\glossary-scan.ps1" -TextFile "稿子.txt"
```

- 按个人词表把**所有候选误听**连行号列出来，**只报不改**。
- 用途：几千字的稿子靠肉眼必漏；先拿到候选清单，再逐条按上下文判断（脚本的命中不是结论）。
- 没有词表返回 `MISSING_GLOSSARY`（退出码 2），词表解析不出规则返回 `NO_RULES`（退出码 3）；自测加 `-SelfTest`。

## 10. 交付前自检

- [ ] 词表里的专名是否全文统一？人名、单位有漏改吗？
- [ ] 女性人物是否统一为「她」？
- [ ] 每个改动能否说出依据（词表 / 上下文 / 检索）？
- [ ] 有没有把语气词、口头禅改成书面语？
- [ ] 有没有新增原文没有的信息？
- [ ] 数字、时间、金额有没有被「推断」改掉？改了的是否标了存疑？
- [ ] 中英文之间有没有多余空格？
- [ ] 修正说明只列了真正改动？未改动的声明了？
