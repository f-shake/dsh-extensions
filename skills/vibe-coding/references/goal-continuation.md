# 自动续行（goal 模式）· 公共规范

**唯一真源。** 各阶段文件只留指针与「本阶段特有条款」，**不复述这里的规则**——规则要改，只改这一份。

> 📖 **只给主对话用。** 依赖 `create_goal` / `update_goal` / `ask_user_question`，它们只在主对话的回合里可用。**装备与收口一律由主代理做**；子代理拿不到这些工具（`ask_user_question` 对它直接返回 `DELEGATED_CALLER`）。

### 前置：本文件条件性适用（先判断，再照做）

1. **没有 goal 类工具**（`create_goal`/`update_goal`/`get_goal`；例如 Claude Code 就没有这类工具）→ **整份忽略**，**本流程退化为「做一段停一次、由用户打『继续』」**（§5 的 `pause` 条款不适用，那时连工具都没有）。**不许自造并行机制，也不许假装「我会自己接着做」。**
2. **不确定有没有工具** → 按第 1 条办（fail-closed）。猜错的代价是无人接管的续跑，比让用户多打几次「继续」严重。

### 只用于阶段二、三（开发、复核）

**本文件服务两个阶段：阶段二（开发）、阶段三（复核）。** 它们的共同点是「一段活可以自己接着做完」。**阶段一、四、五一律不用 goal**——它们的第一步就是等人（答追问 / 选验证方式 / 授权提交），续行只会排出空转的回合。

**阶段三为什么现在能开**：早先版本把阶段三排除在外，理由是「续行不感知子代理，一空闲就来催，催出假收敛」。这个前提在当前 DSH 上已经反转——续行驱动在排下一回合之前会先 `waitForChildren`（0.2.1-alpha.3 起）：子代理没结算就不排；子代理结算时会先唤醒一个回合，把回执送到主代理手上。于是「送审 → 读回执 → 判断 → 修复 → 再送审」天然串行，续行只负责把轮与轮之间接起来。

**但收敛判据不因此放宽**（§1 的边界原则同样适用）：

- 续行排出的回合**不构成收敛证据**——收敛只能由子代理对最终版本的逐条回执证明（`phase-3-auto-review.md` §4）；
- 「连续 3 轮不收敛 → 升级人工」**一条都不放宽**，不试第 4 轮；
- 升级人工那一刻要先把本阶段的 goal 收口（§4），否则它会在你报告的同时继续排回合。

**平台前提**：上面那条依赖驱动「等待子代理」。**若不确定驱动是否如此（较老的 DSH，或别家 harness）→ 阶段三按一轮一停跑**：宁可多问一次，也不要拿假收敛冒险。判据写在 `phase-3-auto-review.md` §3。

**结论：两个阶段各自装备、各自收口**——闸门2 收阶段二的，闸门3 收阶段三的（见 §4），不存在「带进下一阶段」这回事。

---

## 1. 它解决什么

**要治的病**：单轮输出预算有限。长任务做到一半，回合因预算耗尽而结束——看起来像「AI 停下来了」，实际是人被迫打「继续」推它走。把推进交给人肉重试，等于把工作量转嫁给人。

**做法**：用 harness 的 goal 续行。goal 处于 active 且已武装时，**agent 一旦空闲、且手上没有还在推进的子代理**，驱动就自动排下一个回合继续朝目标推进。这样「一路做下去」由机制保证，而不是靠 AI 记得别结束回合。

**边界（很重要）**：续行只管**跨回合的接续**，**不放宽任何阶段自己的上限或判据**——收敛轮次上限、闸门、偏差分级、交付门槛一个都不变。续行是让循环跑得下去，不是让循环跑得更久。

## 2. 用在哪些阶段、哪几个闸门

| 阶段 | 入口（在此装备） | 出口（在此收口） | 本阶段判据 |
|---|---|---|---|
| 阶段二 · 开发 | **闸门1** | **闸门2** | `phase-2-implementation.md` §3 偏差分级 |
| 阶段三 · 复核 | **闸门2** | **闸门3** | 复核是否收敛（`phase-3-auto-review.md` §4） |

**各阶段文件不再重复下面任何规则**，只写本阶段特有的那几条。

阶段目标示例：

- 阶段二：`「vibe-coding 阶段2 · 按已确认计划完成阶段二：改完计划列出的所有文件与关联适配、同步写齐单元测试、自测通过，直达闸门2 停下等人确认」`
- 阶段三：`「vibe-coding 阶段3 · 跑完独立复核循环：派子代理审查、逐项裁决并修复、再送审，直到子代理对最终版本逐条回执确认；连续 3 轮不收敛就停下升级人工，不试第 4 轮」`

> ⚠️ **前缀是硬格式，不是示例。** objective 一律以 `vibe-coding 阶段N · ` 开头（N=2 或 3）。理由：goal 域只有 `active`/`paused`/`blocked`/`complete` 四个相位，**没有阶段字段**；断了线回头看 `get_goal` 时，前缀是唯一能认出「这是哪个 goal」的锚点（见 §7）。
>
> 📌 阶段三的目标里**要把「或连续 3 轮不收敛就升级人工」写进去**——否则第 3 轮撞上限时，你既不能谎报 `complete`，又腾不出槽位。把它写进 objective，收口才是诚实的：这个目标的范围本来就是「跑完循环并停在该停的地方」。

## 3. 装备时机（谁、在哪个回合、什么条件下）

- **谁**：主代理。**只有主对话能建**。
- **哪个回合**：**入口闸门拿到用户确认的那个回合**。**只在「当前回合含人类消息」时才建得出来**——错过那个回合，之后（含自动续行的回合）都建不了。
- **顺序**：在确认到达的那次回合里，**先判断用户有没有拒绝，再 `create_goal`，这是该回合的第一个动作**。
- 带 `max_goal_rounds`（建议 40）给失控兜底——但它**可能真的被跑满**，见 §7 的 `blocked`。
- **装备节奏**：每个阶段**各自建、各自收**——阶段二在闸门1 确认那轮建、闸门2 那轮收；阶段三在闸门2 确认那轮建、闸门3 那轮收。**闸门2 那轮只收不建**（收掉阶段二的），**闸门2 的确认到达之后**才建阶段三的——和「闸门1 建阶段二」是同一个节奏。别把阶段二的 goal 带进阶段三，也别在闸门2 那轮提前建阶段三的（那一轮结束时你还在等人确认，目标会空转到闸门之外）。**阶段二若在阶段条上选了分两步（2a/2b），闸门1 那轮不建、2b 确认时才建**——2a 必须停在「给你看设计」（见 `phase-2-implementation.md` §3.2）。

### 判断「用户拒绝」用语义，不用关键词

**任何表达「慢一点、一段一段来、别自己一路跑、我要盯过程」的话都算拒绝**——「一步一步来」「做完一段停一下」「我自己盯着」「先别自动跑」「不用 goal 模式」都是。**不要只匹配字面词表**——漏判的代价是把用户明确的「我要盯过程」变成自动续行。

判为拒绝 → **不建**，并在同一轮里切回一轮一停（见 §5）。

### fork 支线不得自行装备

**fork 出的支线未经用户明确同意，不得 `create_goal`。** goal 是每会话状态、不随 fork 复制，支线 `get_goal` 看到「没有 goal」就会顺手建一个——结果父支各跑一个阶段目标、并发改同一批文件，互相看不见。

- 要续行 → 先问用户；不同意就按 §5 一轮一停，脚注说明「本条支线续行是关的」；
- **别把「父会话有 goal」当成「我也有」。**

## 4. 出口闸门必须收口

**到达出口闸门的那个回合，先收口，再输出闸门块。**

```
该回合内部顺序（别颠倒）：
  ① 采集数据 —— git status / diff / 测试结果 / 子代理回执，该跑的工具全在这里跑完
  ② update_goal(action: complete)
  ③ 输出闸门块与脚注
```

- **每个出口闸门收的是本阶段的 goal，不是可选项**：闸门1 建的在闸门2 收，闸门2 建的在闸门3 收。不收 → 旧 goal 占着槽位（下一阶段的 `create_goal` 撞 `GOAL_ALREADY_EXISTS`），而且会带着旧目标继续排回合。
- **为什么 ① 必须在 ② 之前**：收口会注入收尾指令，明确要求「**本轮不要再调用任何工具**」。先收口再去跑 `git status`，就只能凭记忆填闸门块的数字——正是 §8 禁止的「凭记忆宣布已完成」。
- **还要问人时，问在收口之前**：如果这一轮本身必须用 `ask_user_question`（如阶段三「3 轮不收敛升级人工」），它要排在 `complete` **之前**——收口后工具就禁用了，顺序反了就只能拿文本凑，见 `phase-3-auto-review.md` §4。
- **顺序反了会怎样**（先报告后收口）：goal 仍是 active，人还在看报告时驱动再排一个回合——凭空多一次回复，闸门等于没关上。
- **本阶段从未建过 goal**（入口闸门当场拒绝）→ 跳过 ②，直接走 ①③。
- **建过、但中途被 §5 停用（paused）** → **照样要收口**：用 `complete` 收掉它，否则这个僵尸 goal 一直占着槽位，下一阶段的 `create_goal` 会撞 `GOAL_ALREADY_EXISTS`。**补救也别推给用户**：那一轮直接 `complete` 收掉即可（`complete` 允许从 `paused` 进入）；只有目标其实没达成、不能谎报 `complete` 时，才请用户 `/goal clear`。别把「用户拒绝过续行」误读成「本阶段没有 goal」。
- **回流到某阶段、要给它重新装备时，先看旧 goal 是不是 `complete`**：只有 `complete` 才腾得出槽位——**`active`/`paused`/`blocked` 一律不行**，`create_goal` 会直接报 `GOAL_ALREADY_EXISTS`。而**你 pause 它也没用**（pause 不腾槽位）。
  - 老阶段目标确实达成过 → `update_goal(action: complete)`，然后重建；
  - 目标没达成、但你手上就是要腾位子 → 你**没有** clear 可用，只能请用户按 `/goal clear`，或先把旧目标做完再 `complete`。**别静默放弃续行**——要么解决，要么明确告诉用户「这个阶段的自动续行现在是关的、原因是什么」。
- 出口闸门用 `complete` 而不是 `pause`：`complete` 表达「本阶段目标已达成」，且**完成态的 goal 可以被下一次 `create_goal` 直接替换**；`pause` 只是**停用**续行（§5 里用户拒绝时你就在同一回合按下它），语义是「停」而不是「完成」——出口闸门要的是后者。

### 收口为什么一定做得成

出口闸门（有 goal 的那些）通常是**自动续行回合**（活干完 → 报闸门块），而 `complete` 在自动续行回合里是**放行**的——收口**不存在被拒的情形**，不必考虑降级路径。阶段三的收口发生在「拿到收敛」或「3 轮不收敛升级人工」那两个回合，同样是自动回合，同样放行。

## 5. 用户说不

用户说「不用 goal 模式」「先别自动跑」等：

- **已有 goal 且已武装** → **就在同一个回合里**调 `update_goal(action: pause)` 停用续行（`pause` 需要人类直接消息授权，此刻正好成立）；
- goal 还没建 → 不建，跳过 §3。

然后说明「已转回一轮一停，每做一段我会停下等你示意」，并告诉他可用 `/goal` 或 Agent Preset 编辑器彻底卸掉续行驱动。**拒绝不需要理由，也不再劝。**

> ⚠️ **你 pause 掉的 goal，你自己再也恢复不了**——那会变成 durable `paused` 相位，只有用户能救（见 §7）。所以说完这句要**明确告诉他**：「想恢复自动续行，用 `/goal resume`」。

## 6. 卡死出口（真该停的时候怎么停）

**只有本阶段判据判定「真该停」的问题**，才把问题提给人：

- **`ask_user_question` 可用时，必须用它**——给选项 + 推荐，**推荐项放第一个并在 label 后标注「推荐」**。它是**阻塞**调用：会冻住自动续行，直到用户回答；答复进来后你在同一个回合里接着做。
- **子代理不能用它**（`DELEGATED_CALLER`）。问题出在子代理的复核里时：**派发任务时就要求它把待裁决项写进最终报告**——子代理结算时会**唤醒一个新的回合**，主代理在**那一轮**里提问（那是新开的一轮，不是当初派发的那个回合）。不要静默丢弃；也不要另派一个子代理去问。
- **工具不可用** → 停下并把待裁决项写明，等答复，**不要静默继续**。

**日常进度播报仍然只播报、不提问。** 用提问代替播报，等于把 goal 模式关掉——每项都问一遍，续行就没意义了。

## 7. 断线（会话重载 / fork / 用户暂停 / 轮次耗尽）

续行中断后**不会自行恢复**，成因不同权限也不同。**发现回合没有被自动接上时，先 `get_goal` 看状态再决定**：

> ⚠️ **当前驱动会先等子代理结算，但别把它当免死金牌。** 排轮条件仍是「主代理 idle + goal active 已武装 + 有余量」，只是排之前会先 `waitForChildren`——子代理没结算就不排。**所以把开发委托给子代理（见 `phase-2-implementation.md` §1.1）不必再 `pause` 续行**；仍要守「同一个文件只允许有一个写者」：子代理在写盘期间，主代理那一回合不要自己去改同一批文件。**较老的驱动不等待子代理**，那种环境下委托期间仍要 `pause`。

### 恢复协议：`resume` 之前先做这四步

**只在「本阶段已经装备过 goal」时才走这四步。** 先 `get_goal`：

- **返回 null 或 `complete`** → 说明这个 goal 已收口（闸门2 / 闸门3 收的、或你收的）。**不用恢复**；下次要装备时按 §3 在入口闸门那个回合重新 `create_goal`。
- **`active` 但 disarmed** → 走下面四步（objective 里只有一句目标，**没有工作清单**，所以别直接 `resume`）：
  1. `get_goal` 取 objective，**按前缀确认是阶段二还是阶段三**；
  2. 读对应阶段文件（阶段二 → `phase-2-implementation.md`；阶段三 → `phase-3-auto-review.md`）；
  3. **重读工作区与 todo**，重建「剩哪几项」；
  4. **一行向用户复述**「按目标，我接下来做 X」，再 `resume`。

第 4 步是让用户**在跑偏前叫停的唯一机会**。**`paused` / `blocked` 不走这套**——见下表，它们各自有用不了的恢复方式。

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| **active，但 disarmed** | 会话重启/fork，或上一个回合被硬截断 | 「未武装」不等于「用户叫停」，但也**不代表他希望继续**。等用户明确要求继续的那次回合，**先走上面四步恢复协议**，再 `update_goal(action: resume)` 接着做。收尾话术：**「续行已掉线，没自动接上——你说一声我就接着做」** |
| **paused** | 用户按的暂停——**也可能是你在 §5 按的** | **你无权恢复，用户说「继续」也不行**：工具会直接拒绝（`GOAL_TOOL_RESUME_PAUSED`），**只有 `/goal resume` 或 Web 控件能救**。说清「**续行已暂停，用 `/goal resume` 我就能接着做**」，然后**停下等** |
| **blocked（`round-limit`）** | 轮次预算耗尽，驱动自动记的 | `resume` **无效**（`GOAL_INVALID_TRANSITION`）：得先 `update_goal(action: edit, max_goal_rounds: <更大的值>)` 抬高上限，再 `resume`。两者都需要用户开口授权——把「要抬到多少」一并告诉他 |
| **complete**，用户要求返工 | 上一次已收口 | 重新 `create_goal`（要求用户那个回合有直接消息） |

> 总则：**恢复续行需要用户开口，你不自行推断「他应该想让我继续」。** 掉线态与暂停态的**话术不能混**——前者不是你干的，后者是用户干的（**或者是你在 §5 干的**，要认账）。

## 8. 轮次边界与硬截断

### 术语（各阶段沿用）

- **「本轮」＝ 本阶段要交付的那一整批工作**，逻辑单位，**可以跨多次回复**。「本轮计划」「本轮输出」「本轮开发」里的「本轮」都是这个意思——说的是这一批，不是这一次回复。
- **「回合」＝ 你的一次回复**，消息单位。
- 例外：「一轮一停」「拆成多轮」里的「轮」指回复或分段，是口语说法。**凡涉及工具授权、续行、截断、驱动排期的地方，一律说「回合」。**

### 权威来源

**权威是工作区实际状态与 todo，不是回合记忆。** 汇报前以工具核实为准——**不凭记忆宣布「已完成」**。

### 被截断时

- 回复被截断、但**回合仍在继续**（工具调用之间的正常切分）→ 如实说明截断点，紧接着继续做。**不得把半个回合当成完整交付。**
- 回合**被硬截断、已经结束**（输出预算耗尽）→ **已知失效点**：
  - 续行被解除武装，且**不会自动重试**；
  - **不要指望自己在那个回合补一句交代**——预算已用完，写不出来。所以**别把回合填到极限**：每完成一项就播报一次并留出余量；
  - **下一个回合可能永远不会自己到来**，用户收不到任何提示。他察觉后说一句「继续」，你在那个回合 `update_goal(action: resume)` 再接着做。
- **不要承诺「本阶段绝不会停」**——承诺的是「**不主动停**」。被硬截断时如实说明断点，不要假装是自己主动收尾的。

## 9. 一页速查

```
入口闸门那个回合：判断拒绝 → 没拒绝就 create_goal（第一个动作，带 max_goal_rounds）
  ↓
自动推进（每完成一项播报一行，不提问；真该停才 ask_user_question）
  ↓
出口闸门那个回合：① 采集数据 → ② update_goal(complete) → ③ 出闸门块
  ↑ 这一步必做：闸门2 收阶段二的、闸门3 收阶段三的（各自收各自的）
  ↓
用户说不 → 同回合 update_goal(pause)，并告诉他「想恢复用 /goal resume」
断线 → get_goal 认前缀（阶段2 / 阶段3）→ 读对应阶段文件 → 重读 todo → 一行复述「我接下来做 X」→ 再 resume
```
