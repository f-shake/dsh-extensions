# @local/vibe-phase-bar

给 vibe coding 五阶段流程用的界面：输入框上方一条阶段面包屑，加号右侧一个「`</>`」按钮控制它的显示与隐藏。配套一个模型侧工具 `vibe_phase`，让模型请求进入下一阶段时，那一格会闪烁等你点击。

## 它做什么

| 位置 | 元素 | 行为 |
|---|---|---|
| `conversation.input.left` | `</>` 按钮 | 常驻。没有流程时点它建出阶段一（不发任何消息）；有流程时点它收起/展开阶段条 |
| `conversation.input.dock` | 五阶段条 | 计划 / 开发 / 复核 / 验证 / 提交。当前阶段高亮，跳过的划掉，被请求的闪烁；分两步时「开发」带 2a/2b 角标 |
| 阶段条上的弹框 | 阶段二 / 阶段四 | 点「开发」问一次性完成还是分两步；点「验证」问跑哪几种验证 |
| 工具 `vibe_phase` | 宿主 | `enter` 进入阶段、`request` 请求确认；请求后对应一格开始闪 |

## 交互细节

- **按钮不发消息。** 条的来路只有两种：点按钮、模型调用 `vibe_phase`。显示与隐藏只由按钮控制，模型推进阶段不会把收起的条顶回来。
- 收起之后若还有阶段在等你确认，按钮右上角出现一个小圆点提醒。
- 点阶段就是确认：宿主把一句话交给 agent（`确认进入阶段 2（开发）。`），同时把状态推进到目标阶段。点更靠后的阶段等于跳过中间闸门，消息里会写明跳过了哪几段；点更靠前的是回退。
- **阶段一是例外：它不发消息。** 点「计划」做两件事：把 `/vibe-coding ` 填进输入框（与在 `/` 菜单里选技能落下的文本一致，光标在末尾），同时把宿主状态清回阶段一（`open` 的 `fresh`，同样不发消息）——这样上一轮残留的验证方式、挂起的 pending 都不会跟着新一轮。流程真正的起点是这条命令发出去之后模型调 `enter(1)`；因此点阶段一也不再是「回退」，要重开流程就发这条命令。输入框已有文字时，命令填在最前面、原文字顺延成构想参数（`setDraft` 会清掉内联引用 chip，这是已知代价）；已经以 `/vibe-coding` 开头时不重复填。
- **阶段二**：一次性完成 → `确认进入阶段 2（开发）。`；分两步 → 先 `2a`（只做界面与交互、演示数据把流程走通），停在 2a 时再点「开发」直接进 `2b`（完整实现与单测），不再弹框。
- **阶段四**：勾选的验证方式（全量单元测试 / 改动相关单元测试 / 端到端验证 / 发布测试；默认勾选「全量单元测试」与「端到端验证」）写进消息，模型不再反问。全量与「改动相关」是同一维度的两种粒度（后者只跑这次改动涉及模块的单测），同时勾等于全量，不做额外拦截。一个都没勾时「进入」禁用；要跳过最终验证直接点「提交」。
- 阶段五是两步：第一次点只进入**预提交**——模型列出计划提交的文件和提交信息，但不提交；冷却 2 秒后再点一次才是**授权提交**。
- 条右下角的 `×` 要连点两次才关闭流程（四秒内没有第二次点击就自动收回）。
- 弹框贴着条的上沿展开；Esc 或点面板外部取消，取消不改任何状态。

## 安装

插件装在 profile 里，宿主与客户端两侧一起生效：

```powershell
node C:\Running\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js plugin --profile aa add "@local/vibe-phase-bar@link:<repo>/plugins/vibe-phase-bar"
```

`dsh plugin add` 会同时写入 profile 的依赖与 `dsh.profile.bundles`。装完需要重启 dsh 进程（客户端包在页面加载时取）。

## 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `precommitCooldownMs` | `2000` | 预提交到授权提交之间的最小间隔，单位毫秒 |

## 接口

宿主只暴露四条同源路由（`ctx.webServer`，前缀 `/vibe-phase`）：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/vibe-phase/state?session=<id>` | 读当前阶段状态，没有状态时为 `null` |
| POST | `/vibe-phase/confirm` | `{ session, phase, options? }`：推进阶段并给 agent 发一条用户消息 |
| POST | `/vibe-phase/open` | `{ session, fresh? }`：没有状态时建出阶段一，不发消息；已有状态原样返回。`fresh: true` 时把已有状态清回阶段一（点「计划」重开用），仍不发消息 |
| POST | `/vibe-phase/reset` | `{ session }`：关闭流程、清掉状态 |

`options` 是可选的：`{ devSplit?: boolean, verify?: ('unit'|'unit-scope'|'e2e'|'release')[] }`。
`verify` 去重后按固定顺序排，空数组或含未知 id 一律 400。
三个 POST 只收 `application/json`（跨站表单发不出这个头，等于一道简易 CSRF 闸），
缺 `session` 一律 400 `missing-session`，请求体不是对象则 400 `bad-body`。

客户端每 1 秒轮询一次。不做会话事件订阅，是因为外部客户端插件没有公开的事件订阅口；不做自定义投影，是因为外部插件不能写自定义会话事件。

## 已知限制

- 状态只在宿主进程内存里。重启后阶段条消失、按钮回到「开始」，流程从头开始。
- 点按钮建流程时会挂上该会话当前的 agent；会话还没有 agent（页面刚开、一句话都没发）时，点阶段二~五会 409，条尾提示「确认失败，请再点一次」，会话跑起来后再点就能用（阶段一不发请求，不受影响）。
- 确认失败只在条尾留一句话（四秒后消失），更细的原因看控制台。
- 宿主没有 `webServer` 时（无界面的部署），工具照常可用，界面不出现。
- 模型不调用 `vibe_phase` 时，条不会自己出现——按钮能把它显示出来，但模型不知道流程开始了。
