## 2. 技术方案

沿用现状：宿主持有权威状态、客户端每秒轮询、点击后本地乐观置位。

新增两处能力：

1. **确认请求带选项**。`POST /vibe-phase/confirm` 的 body 增加可选 `options`：
   `{ devSplit?: boolean, verify?: string[] }`。`planConfirm()` 多接一个参数，把选项编进
   发给模型的那句话，同时记进状态（供角标与悬停说明用）。
   否决「客户端另发一次请求只记选项」：两次请求之间用户可能又点了别的阶段，状态会打架。
2. **弹框渲染在阶段条这一侧**。客户端本地 `dialog` 状态（`'dev' | 'verify' | null`），
   面板 `position: fixed` 贴在条上沿，不依赖不存在的宿主弹窗接口。
   否决「中央模态」：条是小控件，中央模态把注意力从输入框拉走；
   否决「绝对定位挂在条内」：条在 `scrollBody` 里，`overflow` 会裁掉向上突出的部分。

另新增 `POST /vibe-phase/open`：无状态时建一个阶段一状态，不发消息（D1 用）。

不引入新依赖，仍然只 require `react`。

## 3. 系统结构

```
点按钮 ── 无状态 ──► POST /vibe-phase/open ──► 状态：phase 1（无消息）
        └─ 有状态 ──► 本地 hidden 开关（不发请求）

点「开发」─► 弹框（单选）──确认──► POST /confirm { phase:2, options:{ devSplit } }
                                    ├─► 状态：phase=2, devMode, devStep
                                    └─► followup(「确认进入阶段 2a…」/「确认进入阶段 2…」)
停在 2a 再点「开发」──► POST /confirm { phase:2 }（无弹框）──► devStep=b + followup

点「验证」─► 弹框（多选）──确认──► POST /confirm { phase:4, options:{ verify:[…] } }
                                    ├─► 状态：phase=4, verify
                                    └─► followup(「…验证方式：全量单元测试、端到端验证。」)

点「计划/复核/提交」──────────► POST /confirm（与现在一致，无 options）
```

## 4. 数据结构

宿主状态新增三个字段：

```js
{
  // 既有：phase, pending, skipped, precommit, authorized, precommitAt, version
  devMode: 'single' | 'split',            // 阶段二本轮走法，默认 single
  devStep: 'a' | 'b' | null,              // split 时的子步；single 时 null
  verify: ('unit' | 'e2e' | 'release')[], // 阶段四选定的方式，默认 []
}
```

- `applyEnter(state, phase)`：进入阶段二以外的阶段时把 `devMode` 复位 `single`、`devStep` 置 `null`；
  进入阶段二时不动（模型直进 = 一次性完成）。
- 进入阶段五时清空 `verify`（下一轮重新选）。
- `publicState()` 增加这三个字段。

HTTP：

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| POST | `/vibe-phase/confirm` | `{ session, phase, options? }` | `{ ok, state, reason, quiet }` |
| POST | `/vibe-phase/open` | `{ session }` | `{ ok, state }`（已有条目原样返回，不发消息） |

`options.verify`：取值必须落在三个 id 内，去重后按固定顺序排；空数组或含未知值一律 400。

## 5. 模块划分

| 模块 | 负责 | 不负责 |
|---|---|---|
| `planConfirm` | 校验选项、推进状态、生成给模型的一句话 | 不渲染、不发消息 |
| `/confirm` | 请求体与选项校验、followup、错误码 | 不判断该不该进 |
| `/open` | 无状态时建阶段一状态 | 不发消息、不建 agent、不动已有状态 |
| 客户端按钮 | 显隐切换、无状态开条、待确认小圆点 | 不持有权威状态、不发消息 |
| 客户端弹框 | 收集选项、默认值、焦点与关闭、随请求提交 | 不推断阶段、不拼消息文案 |
| 客户端条 | 轮询、渲染、角标、点击分流 | 不改状态字段语义 |

## 6. 交互逻辑与文案

| 动作 | 发给模型的消息 |
|---|---|
| 点「开发」选一次性完成 | `确认进入阶段 2（开发）。` |
| 点「开发」选分两步 | `确认进入阶段 2a（开发·前端与设计）：这一轮只做界面与交互——布局、样式、演示数据把流程走通，做完停下来把设计给我看；完整实现与业务逻辑留到 2b。` |
| 停在 2a 再点「开发」 | `确认进入阶段 2b（开发·完整实现）：按已确认的设计一次性做完完整实现与单元测试。` |
| 点「验证」并选方式 | `确认进入阶段 4（验证），验证方式：全量单元测试、端到端验证。按选定方式执行，不要再问我选哪种。` |
| 前跳 | 现有前缀保留，验证方式接在后面：`确认跳到阶段 4（验证），跳过阶段 3。验证方式：…` |
| 停在 2a 直接点「复核」 | `确认跳到阶段 3（复核），阶段 2b 未做。`（阶段的 2 不进入跳过集合） |

弹框表现：

- 贴条上沿的面板，宽 `min(92vw, 320px)`，标题一行，选项纵向排列，底部「取消 / 进入」。
- 打开时焦点落到第一个选项；Esc 关闭；点面板外部关闭；关闭后焦点回到被点的 chip。
- 阶段二单选（默认「一次性完成」，第二项标注「先看设计，再做完整实现」）；
  阶段四多选（默认前两项，每项一行说明）。
- 阶段四一个都不勾：`进入` 禁用，旁边提示 `至少选一种验证方式`。
- 条上角标：分两步时「开发」右上角 `2a` / `2b`；阶段四选了方式后，悬停说明追加之选方式。

## 7. 异常情况

| 场景 | 表现 | 文案 |
|---|---|---|
| `/open` 失败 | 条不出现，按钮维持原样 | 无提示（控制台留痕） |
| 确认时 agent 已结束（409） | 弹框关闭、状态回滚 | `确认失败，请再点一次` |
| 选项非法（400） | 不改状态、不关弹框 | `选项无效，请重新选择` |
| 轮询失败 | 保留上次状态 | 条尾 `状态未同步` |
| 两个标签页同时操作 | 各自弹框、各自提交，以宿主返回为准 | — |
| 弹框打开时模型请求进阶段 | 不自动关弹框（用户手上有未完成的动作） | — |

## 8. 边界条件

- 无流程：按钮在，点击建阶段一，不发消息。
- 关掉流程（条上的 ×）之后：条消失，按钮仍在，点它可重新建一个阶段一。
- 375px：弹框宽 `92vw`，选项不截断；条本身横向滚动不变。
- 深浅色：只用主题变量。
- `prefers-reduced-motion`：弹框不做动画。
- 键盘：Tab 可达每个选项，Esc 关闭，Enter 触发「进入」。
- 弹框打开期间再点 chip 不叠加第二个弹框。
